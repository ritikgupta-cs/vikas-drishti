You are a senior full-stack engineer, UI/UX designer, AI/ML architect, and government-tech product designer.

Build a complete, polished, responsive web application prototype called:

VIKAS-DRISHTI
AI-Powered MPLADS Risk Intelligence & Monitoring System

The application is being developed as a Smart India Hackathon 2026 prototype for the Ministry of Statistics & Programme Implementation (MoSPI) problem statement SIH26102.

==================================================
1. PROJECT PURPOSE
==================================================

VIKAS-DRISHTI is an AI-powered risk-intelligence and monitoring layer for the MPLADS ecosystem.

MPLADS = Members of Parliament Local Area Development Scheme.

The system should NOT replace the existing official MPLADS digital ecosystem/eSAKSHI.

Instead:

eSAKSHI = manages and monitors the implementation workflow

VIKAS-DRISHTI = analyzes available project, financial, progress, payment, location and text data to identify unusual patterns and prioritize projects for verification.

The core objective is:

Detect → Explain → Recommend → Verify → Track

The system should help authorized government officers identify projects that may require attention instead of manually checking every project with equal priority.

IMPORTANT:
The system must never claim that an anomaly is confirmed fraud.

Use terminology such as:
- Potential anomaly
- Risk signal
- Risk alert
- Duplicate possibility
- Verification required
- High-risk project
- Requires officer review

The AI supports decision-making. The final administrative decision always remains with the authorized human officer.

==================================================
2. CORE PROBLEM
==================================================

MPLADS involves a large number of development works and therefore generates large amounts of:

- Expected completion dates

Manually monitoring every project continuously is difficult.

The system should identify:

1. Cost anomalies
2. Cost overruns
3. Delayed projects
4. Low physical progress
5. Spending-progress mismatch
6. Potential duplicate works
7. Unusual project patterns
8. Potential payment/expenditure irregularities
9. Compliance gaps
10. Emerging risk trends

The output should be an intelligent risk-prioritization system rather than a simple dashboard.

8. COST ANOMALY DETECTION
==================================================

Implement a cost anomaly detection module.

Input fields:

- Project ID
- Project type
- District
- Location
- Estimated cost
- Actual expenditure
- Sanctioned amount
- Project date
- Project duration
- Implementing agency

Calculate:

Cost Deviation:

Actual Cost - Estimated Cost

Cost Deviation Percentage:

((Actual Cost - Estimated Cost) / Estimated Cost) × 100

Compare projects with similar:

- Project types
- Geographic areas
- Time periods
- Project sizes

Use anomaly detection.

Preferred algorithm:

Isolation Forest

Technical explanation:

Isolation Forest is an unsupervised anomaly detection algorithm that isolates unusual observations using random partitioning.

Important:

Isolation Forest identifies unusual patterns.

It does NOT directly produce the final risk score.

It does NOT prove fraud.

Its output should be transformed/calibrated into an anomaly severity score and then passed to the risk scoring engine.

Example:

Similar projects:
₹19L–₹23L

Current project:
₹48.45L

System:

1. Detects unusual cost
2. Generates cost anomaly signal
3. Calculates anomaly severity
4. Converts it into risk contribution
5. Shows explanation
